# 付费获客基础：资产、指标、预算和实验

付费获客经常从“先充一点钱试试”开始。广告很快获得展示和点击，创作者也按约发布了内容，但团队随后发现，购买事件没有记录，后台归属在个人账户，落地页的注册口径与支付系统不一致，合作方离场后还带走了权限。钱已经花掉，却没有留下能够指导下一轮的证据。

一轮合格的付费实验，购买的除了流量，还有一次受控学习。它应当回答：哪类人看到了什么承诺，经过哪条路径，在哪一层流失，获得一位合格客户付出了多少完整成本，以及再投入一笔钱时准备验证什么。账户、事件、指标和停止条件若没有提前定义，后台报表再丰富也很难回答这些问题。[1][2]

本章先建立 Meta、Google Ads、创作者合作和其他付费分发都能共用的基础。具体平台后台和逐层诊断放在下一章，创作者选号与 Brief 放在后续章节。

## 投放前先画清资产和责任

付费账户通常不是一个孤立账号。它连接企业或个人主体、登录身份、广告账户、品牌主页、域名或 App、付款资料、数据源、分析工具与转化事件。任何一项归属不清，都可能在交接、申诉或异常扣费时变成单点故障。

开始前可以画一张资产图：

`经营主体 → 业务资产容器／经理账户 → 广告账户 → 品牌身份 → 域名或 App → 数据源与事件 → 付款与报表`

不同平台的名称会变化，责任问题相对稳定：

| 资产 | 需要确认的事项 | 常见风险 |
|---|---|---|
| 经营主体 | 公司或个人名称、地区、验证资料、合同与发票抬头 | 付款、验证和申诉主体互相冲突 |
| 业务容器／经理账户 | 谁拥有，谁是主管理员，是否有备用管理员 | Agency 或离职员工成为唯一控制人 |
| 广告账户 | 账户编号、币种、时区、付款方式、账单联系人 | 币种或时区错误后难以修正，账单无人处理 |
| 品牌身份 | Page、频道、主页、域名、App 和商店页归属 | 广告能投，品牌内容和消息却无法管理 |
| 数据源 | Pixel、Dataset、SDK、服务器事件、GTM、GA4 等 | 事件发到他人资产，代码无人维护 |
| 转化目标 | 事件名称、触发条件、主要／次要用途、价值与去重 | 页面浏览被当成购买，重复上报抬高结果 |
| 外部合作方 | 访问范围、期限、交付、撤销、数据导出与事故责任 | 共享密码、权限过大、合作结束后仍可操作 |
| 恢复材料 | 账户 ID、管理员、恢复邮箱、付款凭证、验证与申诉记录 | 封禁、盗号或人员失联时无法证明归属 |

相关案例中的 Meta 案例把个人身份、业务容器、广告账户和 Page 分开解释，并把 Pixel、SDK 与广告素材研究工具放进同一工作流。[1] 这种拆分比记住某一版后台菜单更有用。平台界面会改名，所有权、管理权、数据权和付款责任仍需要逐项记录。

外部人员应通过平台提供的角色和授权机制进入，不共享个人密码。Meta 当前区分广告账户管理员、广告主和分析员等角色，并明确反对多人共享个人账户或创建不真实身份；Google Ads 也提供只读、标准、账单和管理员等不同访问级别。[7][10] 实际授权遵循最小权限：只做报表的人不需要改预算，只做素材的人不需要管理付款，Agency 也不应成为客户资产的唯一管理员。

## 先让产品和承接页面具备接流量的条件

账户建好并不代表已经适合投放。付费流量会把现有问题更快暴露出来。投放前至少完成一次从广告承诺到付款或核心价值的人工走查：

1. 广告、创作者内容、落地页和产品使用同一组核心承诺；
2. 页面在主要设备、浏览器、地区和网络条件下能够打开；
3. 价格、试用、续费、取消、退款和必要限制能被用户看懂；
4. 注册、验证、下载、支付和核心任务没有已知阻断；
5. 帮助、联系、隐私和条款入口可用；
6. 关键事件能在分析和广告后台被正确接收；
7. 用户成功完成后，团队能够确认真实订单、退款和后续使用。

若产品仍在验证期，付费流量可以承担用户研究、Message 测试和漏斗排错，规模必须受控。此时的目标是减少未知，不宜把第一次点击成本或注册成本直接写进长期增长预测。

## 用事件字典统一业务与平台

“转化”只是一个类别，不是一项可以直接使用的指标。浏览页面、开始试用、完成核心任务和付款都是转化事件，但经营价值不同。团队需要在投放前建立事件字典。

| 字段 | 示例 | 需要回答的问题 |
|---|---|---|
| 事件名称 | `purchase_completed` | 是否稳定、可读，是否跨工具保持一致 |
| 业务含义 | 支付成功且订单有效 | 发生什么才算一次 |
| 触发位置 | 支付服务端确认后 | 由前端、服务端还是第三方发送 |
| 主体与去重 | `order_id` | 刷新、重试或多端上报会不会重复 |
| 金额与币种 | 净支付金额、USD | 是否包含税费、折扣和退款 |
| 优化用途 | 主要目标 | 平台能否用它优化和出价 |
| 观察用途 | 次要目标 | 是否只进入报表，不影响主要优化 |
| 验证方式 | 测试订单、后台订单和事件日志三方核对 | 怎样证明没有漏报或多报 |
| 负责人 | 产品分析负责人 | 异常由谁排查，多久处理 |

转化层次较多的产品需要把经营目标与诊断信号分开：购买或合格线索可以成为主要目标，浏览、加入购物车或低意向注册先用于定位问题。Google Ads 当前也按 Primary 与 Secondary conversion action 区分出价和观察用途，具体设置仍要按照账户类型和官方说明检查。[4] Campaign 层的配置与诊断在下一章展开。

相关案例中的 Google Ads 演示也把转化配置放在建 Campaign 之前：先准备网站代码、GTM、GA4 和 Google Ads 权限，再决定购买、加购、浏览等事件的优先级。[2] 操作顺序反映了一个业务原则：平台只有收到可靠信号，才可能围绕业务结果学习。

## 数据采集同时有隐私边界

广告事件可能包含页面行为、订单、应用事件、客户资料或线下结果。能够上传不代表适合上传。团队需要明确数据来源、用途、保留时间、访问者、用户告知、同意或其他合法依据，并尽量减少字段。

Meta 当前把网站、App、线下和其他事件逐步组织为 Dataset；Pixel 可以记录网页事件，Conversions API 可以从服务器、网站平台、App 或 CRM 连接营销数据。Meta 官方同时明确，Conversions API 不能用来绕过数据共享政策、iOS App Tracking Transparency 或欧洲隐私规则。[8][9]

Google Consent Mode 根据用户的同意状态调整标签行为。当前官方文档要求在用户作出选择前设置默认状态，并在选择后更新；配置项包括广告存储、分析存储、广告用户数据和广告个性化等。[6] 它是一种技术机制，不能替代地区法律判断、真实的同意界面或内部数据治理。涉及客户名单、再营销、增强型转化、儿童、健康、金融等敏感场景时，应结合目标地区、行业和平台规则单独审查。

## 把指标放回对应漏斗层

付费报表最容易出现的错误，是用上游指标回答下游问题。CPM 低只能说明获得展示较便宜，CTR 高说明某个承诺容易获得点击，ROAS 高也只是在特定归因与收入口径下，广告收入相对广告支出较高。它们都不能单独证明业务健康。[1][3]

常用指标可以这样整理：

| 指标 | 基本公式 | 所在层级 | 使用时必须注明 |
|---|---|---|---|
| CPM | 花费 ÷ 展示 × 1,000 | 购买曝光 | 市场、受众、版位、时间和竞价环境 |
| CTR | 点击 ÷ 展示 | 素材与承诺 | 点击定义、展示口径、创意和人群 |
| CPC | 花费 ÷ 点击 | 到站前 | 链接点击还是全部点击 |
| CVR | 本层目标 ÷ 上一步人数 | 任意相邻两层 | 分子、分母和观察窗口 |
| CPI／CPA | 花费 ÷ 安装或目标行为 | 特定结果 | 事件定义、归因窗口和无效结果处理 |
| CAC | 完整获客成本 ÷ 新付费客户 | 客户获取 | 是否包含媒体、创意、佣金、销售和工具 |
| ROAS | 归因广告收入 ÷ 广告花费 | 广告回报 | 收入口径、币种、退款和归因窗口 |
| ROI | （收益－投入）÷ 投入 | 经营投入 | 收益和投入包含哪些项目 |
| LTV | 客户生命周期贡献的估计 | 长期价值 | 毛利、留存、退款、服务成本和观察周期 |
| 回收期 | 累计贡献覆盖 CAC 所需时间 | 现金效率 | 月付、年付、续费和现金流结构 |

同一指标只有在同一层级、同一公式和相近条件下才适合比较。创作者内容的 Views 不能直接与广告 Impressions 相比，视频播放也不等于看到链接。相关案例中的创作者漏斗专门把 Exposure、Views、Link Exposure、Click、Visit、Signup 和 Paid 拆开，就是为了避免把内容分发结果误写成业务转化。[3]

指标表还应固定四个口径：

- **币种**：支出和收入按哪一天、哪一种汇率换算；
- **归因窗口**：点击或观看后多长时间计入平台结果；
- **成本范围**：只计媒体，还是连同创意、Agency、佣金、工具、销售与内部工时；
- **客户范围**：新客户、回流客户、续费、升级和退款怎样处理。

若团队暂时没有可靠 LTV，可先报告已观察到的首单贡献、续费和留存，不用一个想象中的长期价值为高 CAC 辩护。

## 沿完整路径找损失

网页产品的基础路径可以写成：

`合格曝光 → 点击 → 页面到达 → 注册 → 到达核心价值 → 付费 → 留存`

App 产品还要加入商店页、下载开始、下载完成、首次打开和设备兼容；创作者合作要把观看、看到链接、点击与品牌搜索分开。每多一层，团队就多一个可能的损失位置。

| 现象 | 优先检查 | 不宜立刻做的动作 |
|---|---|---|
| CPM 高 | 市场竞争、人群大小、版位、季节、质量和账户状态 | 只靠提高出价解决全部问题 |
| CTR 低 | 前几秒、标题、首图、问题与价值表达、人群匹配 | 同时换受众、素材、Offer 和页面 |
| 点击多、到站少 | 加载速度、跳转、追踪、误点和网络环境 | 把平台点击直接当网站访问 |
| 到站多、注册少 | 广告—页面一致性、可信度、表单和价格表达 | 用更夸张承诺继续抬 CTR |
| 注册多、价值少 | 用户匹配、Onboarding、技术问题和核心任务 | 只优化注册按钮 |
| 价值多、付费少 | 付费点、权益、价格、采购与支付条件 | 把所有问题归因于素材 |
| 平台购买多、后台订单少 | 事件重复、测试订单、归因和退款 | 直接按平台数字核算收入 |
| 首单可接受、留存差 | 客户质量、承诺兑现、服务成本和产品价值 | 用乐观 LTV 扩大预算 |

这种诊断方式把投放、页面、产品和经营连起来。相关案例中的 Meta 案例也强调，CPI 高可以拆成展示、点击和安装转化，ROAS 低则需要同时检查获客成本与用户价值。[1]

## 平台选择由任务决定

Meta、Google Ads、创作者合作或其他付费渠道没有统一的先后顺序。选择可以先比较四件事：

1. **需求状态**：用户是否正在主动搜索，还是需要通过内容发现问题和产品；
2. **表达方式**：团队是否能持续生产视觉创意、长教程、关键词页面或创作者内容；
3. **数据条件**：转化事件是否可靠，已有样本能否支持更深的优化目标；
4. **经营边界**：价格、毛利、回收期、市场容量和可承受损失是否匹配。

搜索广告更容易承接已经表达出来的意图，信息流和创作者内容更适合创造发现、展示场景或建立信任。实际项目也会交叉：用户看过视频后搜索品牌，或先搜索问题，再被再营销内容提醒。平台选择应从客户路径出发，下一章再具体讨论 Meta 与 Google Ads 的配置和诊断差异。

## 从贡献倒推可承受 CAC

预算不应从“别人一般花多少”开始。先估算一位新客户能够贡献多少，以及现金允许多久收回。

对一次性产品，可以从下面的简化式起步：

`首单贡献 = 实收价格－税费－支付费－退款预期－履约与支持变动成本`

订阅产品还要按实际留存、升级、退款和服务成本估算一段保守观察期内的贡献。可承受 CAC 应低于预期贡献，并留出固定成本、误差和利润空间。若未来续费没有足够证据，先用已观察到的贡献，不把所有潜在续费提前花掉。

例如，一项服务实收 100 美元，支付、交付、退款预期和支持变动成本合计 40 美元，首单贡献约 60 美元。团队若要求首单覆盖获客，并预留 20 美元风险与经营空间，本轮可承受 CAC 上限约为 40 美元。这个数字来自该项目的成本结构，不是广告平台基准。

接着把 CAC 向上游拆开：

`可承受 CPC = 可承受 CAC × 点击到新付费客户的转化率`

若点击到新付费客户的基线为 2%，可承受 CAC 为 40 美元，则可承受 CPC 约为 0.8 美元。基线只有小样本时，应同时计算保守、中性和乐观情景，不把一个精确小数当成确定事实。

## 从所需样本倒推实验预算

实验预算由问题和样本决定。先写清希望观察多少个目标行为，再根据已有转化率倒推需要多少访问或点击：

`所需访问量 = 目标行为数 ÷ 预估访问转化率`

`媒体预算 = 所需点击量 × 预估 CPC`

还应另计素材、创作者、Agency、工具和跟进成本。若目标是验证页面注册，样本可以停在注册；若要验证付费经济，预算必须有机会穿过付款与退款窗口。不同问题需要的样本不同。

Google Ads 当前以平均每日预算管理 Campaign，并按官方页面规定的单日与月度支出边界运行。[5] 平台会更新计算和界面，预算负责人需要以当前账户、币种和官方说明核对，不能把历史演示中的 300 元日预算、5 倍目标 CPA、500／1,000 美元起投或固定学习周期当成通用要求。[1][2]

小预算无法支持最终付费样本时，仍可把实验向前移：先验证目标用户能否识别承诺、点击是否来自正确意图、页面是否被理解，随后用访谈、手工销售或更长观察补足。需要明确写成“上游验证”，不能宣称 CAC 已成立。

## 在开始前写停止条件

停止条件用于保护现金，也防止团队因为早期好坏波动频繁改动。它至少包含：

- **最大现金损失**：本轮媒体与完整执行最多花多少；
- **最长观察时间**：考虑购买周期、报表延迟和退款后，何时必须复盘；
- **最低执行质量**：素材、页面、事件和投放是否按计划运行；
- **最低信息样本**：至少获得多少合格点击、价值事件或有效对话；
- **安全触发器**：异常扣费、账号入侵、政策风险或数据泄露时立即暂停；
- **经济触发器**：即使采用合理改善情景，CAC 仍明显高于可承受范围；
- **继续条件**：哪一层出现信号，下一轮只准备修什么。

停止不等于渠道永久无效。一次实验可能只证明当前受众、素材、Offer 或页面没有成立。决定应写清证据和适用范围，例如“这组关键词在当前价格与页面下无法达到可承受 CAC”，而不是“Google Ads 对这个行业没用”。

## 受控比较与自动分配承担不同任务

若目标是学习一个变量，其他条件尽量保持一致。例如只比较两种价值表达，就让受众、页面、预算、时间和优化事件尽量相同。否则结果变化无法归因。

若目标是让一个已经验证的 Campaign 获得更多总结果，可以允许平台在素材或受众之间自动分配预算。相关案例中的 Meta 演示用广告组预算和 Campaign 预算说明这两种思路：前者便于给各组相近机会，后者让系统把更多预算移向当前表现较好的组。[1] 平台产品名称会更新，实验控制与自动配置的区别仍然存在。

Google Ads 当前的 Experiments 可以在原 Campaign 与实验之间拆分预算和流量，并在设定周期内比较结果。[11] 使用任何实验工具时，都要提前确定主指标、分流、时间、排除项和判断规则。不要看到第一天的领先就结束，也不要在实验中途不断更换素材、页面与出价。

## 素材按关系深度安排信息

同一条内容不适合承担所有阶段的任务。可以按用户与产品的关系深度分三层：

- **陌生用户**：说明问题、适用场景和最核心价值，让合适的人愿意多看一步；
- **已经互动或到站的人**：补充产品演示、案例、限制、价格、试用和可信证据；
- **已经使用或购买的人**：解释升级、复购、续费、推荐和新场景。

再营销和客户名单需要适当的数据依据、用户告知与平台合规。案例、评论和使用结果必须真实并获得必要授权。为了提高 CTR 虚构评论、制造错误期待，通常会把损失转移到页面、退款、投诉和账户风险。

## 创作者付费也使用同一套算账方法

创作者合作的报价常以粉丝、播放或内容数量表达，经营判断仍要回到完整漏斗：

`曝光 → 观看 → 看到链接 → 点击 → 访问 → 注册 → 到达价值 → 付费`

每位创作者使用独立链接、UTM 或优惠码，记录发布日期、内容形式、费用、授权范围和观察窗口。长视频可能有持续搜索和推荐，短内容也可能通过品牌搜索或直接访问产生后续影响。平台链接、自报来源、品牌词和付款数据可以互相补充，不能强行合成一个精确归因比例。[3]

历史案例中的地区 CPM、单条报价和 Agency 日产量来自特定市场与时点，只适合说明当时怎样估价。[3] 新项目应采集目标品类、地区和创作者的当前样本，并在同一层级比较。便宜地区可以验证创意制作和合作流程，却不能直接证明主要市场的需求、定价和付费率。

## Agency 应放大已验证的工作

外部团队可以增加建联、制作、投放和报表产能，但不会自动补齐定位、产品价值和转化路径。适合交付给 Agency 的流程通常已经具备：

- 目标用户和排除标准清楚；
- 素材与 Offer 有初步证据；
- 页面、事件和付款能正常工作；
- 合格结果、重复触达和无效流量有统一定义；
- 客户保有账户、数据、素材和合同权利；
- 发生异常时有暂停、撤权和恢复流程。

合同至少写清候选数量与发布数量、质量门槛、重复率、版权和使用范围、广告披露、数据处理、报表口径、付款、退款或补量条件、事故通知与权限撤销。每天触达多少人或产出多少内容只是产能，不代表增量客户。

## 账户安全是投放系统的一部分

广告账户同时连接付款、客户数据、品牌身份和大额预算，安全检查不能等到出事后再做：

1. 每位操作人使用自己的真实身份与账户，不共享登录凭据；
2. 开启两步验证，并保留可访问的恢复方式；
3. 至少有两名可信管理员，避免唯一管理员失联；
4. 按角色授予最低必要权限，定期删除离职人员和过期合作方；
5. 检查异常 Campaign、预算、付款、登录设备和经理账户关联；
6. 对新增管理员、付款变更和异常消耗设置通知；
7. 核对邮件发件域名和登录网址，不从陌生附件或扩展进入后台；
8. 保存账户 ID、验证、付款、合同、素材授权和申诉证据；
9. 出现盗号、恶意软件或未授权广告时先止损，再走平台官方恢复流程。

Google Ads 当前建议定期审查用户权限、删除不活跃用户、避免共享登录，并为每位用户授予最低访问级别；两步验证和最新恢复信息能降低账户被接管或无法找回的风险。[10][12] Meta 也建议启用两步验证、登录提醒和业务通知，检查可疑设备与浏览器扩展。[13]

购买账户、伪造身份、轮换资产或通过 IP、静置时长等方式规避审核，会增加所有权、付款与封禁风险，也无法形成可持续经营资产。遇到误判应保留证据并使用官方申诉和恢复渠道。

## 用一页实验 Brief 开始

一轮实验可以在上线前写成一页：

| 项目 | 需要填写的内容 |
|---|---|
| 业务问题 | 本轮要减少哪个未知 |
| 目标用户 | 地区、角色、任务、阶段和排除条件 |
| Message／素材 | 主要承诺、证据、格式与授权 |
| Offer | 试用、购买、预约或其他下一步 |
| 承接路径 | 广告／内容、页面、产品、付款和后续 |
| 主要事件 | 用于判断与优化的业务结果 |
| 诊断事件 | 帮助定位损失的上游动作 |
| 指标口径 | 公式、币种、窗口、成本和客户范围 |
| 基线与假设 | 已有数据、保守／中性／乐观情景 |
| 预算 | 媒体、素材、合作、工具和跟进成本 |
| 变量 | 本轮只改变什么，哪些保持不变 |
| 停止与安全 | 最大损失、观察期、样本和异常触发器 |
| 决策 | 继续、调整、停止分别需要什么证据 |
| 负责人 | 账户、数据、素材、付款、复盘和恢复责任 |

实验结束后，不只保存一张平台截图。应保留设置、素材版本、页面版本、事件测试、每日数据、真实订单、退款、用户质量、异常和决策。下一轮首先继承这些证据，再决定改变一个变量还是扩大投入。

## 最后检查清单

- 经营主体、业务容器、广告账户、品牌身份、域名／App、数据源和付款归属清楚；
- 每项关键资产都有主管理员、备用管理员、恢复方式和离场撤权流程；
- 外部合作方通过平台角色进入，没有共享个人密码；
- 页面、注册、核心价值、支付、条款与支持路径已经人工走查；
- 事件字典写清业务含义、触发、去重、金额、用途和负责人；
- 主要转化与诊断事件已经区分，并用真实测试核对；
- 数据采集有明确目的、最小字段、访问范围和适用的用户告知／同意；
- Consent Mode 或服务器事件没有被当成规避隐私要求的工具；
- CPM、CTR、CPC、CVR、CPA、CAC、ROAS、ROI、LTV 和回收期各自位于正确层级；
- 指标记录了币种、归因窗口、成本范围和客户范围；
- 平台点击、网站访问、产品事件、订单和退款分别保留；
- ROAS 没有代替完整 ROI，预测 LTV 没有代替已观察贡献；
- 漏斗覆盖曝光、到站、注册、价值、付费和留存；
- 平台选择基于需求状态、表达方式、数据和经济边界；
- 可承受 CAC 从贡献、风险空间和回收期倒推；
- 预算从问题、基线和所需样本倒推，没有采用固定起投数字；
- 小预算只验证上游时，结论明确限定在上游；
- 实验前已经写好最大损失、观察期、样本与安全停止条件；
- 受控实验一次只改变少量主要变量；
- 自动分配用于追求整体结果时，没有被误写成公平变量比较；
- 陌生、互动和客户人群使用不同深度的信息；
- 评论、案例、优惠和合作关系真实、授权并准确披露；
- 创作者的观看、链接曝光、点击、到站和付费分别归因；
- 历史 CPM、预算、学习期和 Agency 产能没有被当作当前行业基准；
- Agency 只获得必要权限，合同写清资产、数据、版权、报表与事故责任；
- 全员启用两步验证，定期检查用户、关联账户、异常消耗与恢复信息；
- 没有购买账户、伪造身份或使用规避审核的操作；
- 复盘保留设置、素材、页面、事件、订单、退款、异常和决定。

付费获客成熟的标志，不是账户里有多少 Campaign，也不是某一天的 ROAS 看起来很高。团队需要拥有自己的资产，知道每个事件代表什么，能把指标放回真实漏斗，从贡献和样本推导预算，并在达到停止条件时作出有边界的决定。这样，一笔测试费即使没有带来可规模化的客户，也能留下下一轮可使用的证据。
